# COVER 복구용 PA 옵션 참고서

옵션 문법과 선택 조건을 담은 로컬 참고서다. 진단 순서는 [분석 설정 가이드](analysis-guide.md), 실행·성공 판정은 [PA 실행 계약](pa-runtime.md)을 따른다. 필요한 절만 읽는다.

이 문서의 예제는 `.conf` 파일에 넣는 형식이다. 값을 받는 옵션은 `이름=값`, 플래그는 `이름`으로 적는다. 원문의 `--` 표기는 분석기 명령행 설명이며, 이 옵션들을 `tmpa project.db global.db win|linux pa.ini` 뒤에 직접 붙이지 않는다.

문법·예제와 버전 표시는 [출처 기록](guide-sources.md)의 S1·S2를 기준으로 한다. **문서 확인과 실제 PA 검증은 별개다.** 별도 표시가 없는 옵션의 도입 버전·허용값 전체 범위는 원문에서 미확인이다. PA 버전이 미확인이라는 이유만으로 실행 불가로 판정하지 않되, 확인된 문법과 현재 오류 근거가 있는 후보만 복사본에서 검증한다.

## 컴파일러 종류와 버전

사용한 컴파일러 실행 파일, 같은 빌드의 버전 출력, 실제 컴파일 명령이 근거다. include 경로나 제품 설치 폴더 이름만으로 버전을 고르지 않는다. 아래 버전 숫자는 원본 컴파일러를 표현하며 PA 자체 버전이 아니다. [S1](guide-sources.md#sources)

| 옵션 | 문법과 예제 | 적용 조건 | 확인 범위 |
| --- | --- | --- | --- |
| `gnu_version` | `gnu_version=130200` — GCC 13.2.0 | 실제 GCC 버전 `x.y.z`를 `x*10000+y*100+z`로 변환 | GNU 호환 모드 활성화. 수용 가능한 컴파일러 버전 전체 범위·PA 도입 버전 미확인 |
| `clang_version` | `clang_version=170100` — Clang 17.1.0 | 실제 Clang 버전을 같은 계산식으로 변환 | Clang 모드 활성화. 수용 범위·PA 도입 버전 미확인 |
| `microsoft_version` | `microsoft_version=1943` — `cl` 19.43 | 실제 `cl` 버전 확인. S1 예제는 VS 2022 17.13.3과 연결 | GCC 계산식을 적용하지 않음. S1에는 `1916`, `1929` 예제도 있음 |
| `gcc`, `g++` | 한 줄에 `gcc` 또는 `g++` | 원래 GNU C / C++ 모드가 필요한 경우 | 각각 C / C++ 언어 모드를 설정하므로 활성 언어 옵션과 함께 확인 |
| `clang`, `microsoft` | 한 줄에 `clang` 또는 `microsoft` | 해당 컴파일러 호환 모드가 필요한 경우 | S1은 `clang`을 Clang C 호환 기능으로 설명. 옵션 이름만으로 C++ 표준을 정하지 않음 |

현재 설정의 다른 컴파일러 계열 옵션을 근거 없이 추가하거나 혼합하지 않는다. 원래 명령의 언어 선택과 [언어 표준](#language)도 함께 확인한다.

계산 예: 실제 버전 출력이 GCC 5.3.0이면 `gnu_version=50300`, GCC 12.3.0이면 `gnu_version=120300`이다. S1의 GCC 5.3 예제에 적힌 `100200`은 10.2.0을 표현하므로 그대로 사용하지 않는다.

## 언어 표준과 Microsoft 확장

원본 명령의 C/C++ 선택, `-std`·`/std`와 활성 PA 옵션을 대조한다. 표준 옵션이 없으면 해당 실행 파일·버전의 로컬 매뉴얼이나 같은 옵션으로 얻은 언어 모드 증거를 확인한다. 확인할 수 없으면 기본 표준을 미확인으로 남기며 최신 표준으로 임의 상향하지 않는다.

| 구분 | S1에 기재된 `.conf` 플래그 | 주의점 |
| --- | --- | --- |
| C | `c`, `c89`, `c99`, `c11`, `c17`, `c18`, `c23` | `c`만으로 특정 최신 표준을 선택했다고 판단하지 않음 |
| C++ | `c++`, `c++03`, `c++11`, `c++14`, `c++17`, `c++20`, `c++23` | 원본 `gnu++17`을 그대로 PA 옵션으로 만들지 말고, GNU 호환 모드와 C++17을 함께 검토 |
| MSVC C | `ms_c11`, `ms_c17`, `ms_c23` | 실제 MSVC 언어 모드에 한정 |
| MSVC C++ | `ms_c++14`, `ms_c++17`, `ms_c++20`, `ms_c++23`, `ms_c++latest` | `latest`가 가리키는 기능을 고정된 표준으로 간주하지 않음 |
| Microsoft 확장 | `ms_compatibility`, `ms_extensions` | 주로 Clang에서 Microsoft 문법 호환이 필요할 때 검토. `microsoft_version`을 지정하는 것과 같지 않음 |

위 목록은 문서에 나온 철자이며, 각 플래그의 PA 도입 버전은 미확인이다. COVER 인터페이스가 C/C++ 옵션을 추가할 수 있으므로 `.conf`에 없다는 이유만으로 언어 모드가 없다고 판단하지 않는다. 최종 분석 명령도 확인한다.

S1의 MSVC 예제: 실제 대상이 Windows 64비트, `cl` 19.16, MSVC C++17로 확인된 경우에만 아래 조합을 참고한다. 기존 설정 전체를 교체하는 템플릿이 아니다.

```text
target=win64
microsoft_version=1916
ms_c++17
```

[S3](guide-sources.md#sources)의 오래된 기본 표준 표에는 추정·불일치가 섞여 있어 현재 컴파일러의 기본값 판정표로 사용하지 않는다.

## target과 타입 기본값

`target`은 원본 소스를 컴파일할 CPU·운영체제·비트 수를 표현한다. `tmpa` 실행 인자의 `win` / `linux`는 분석기를 실행하는 PC를 나타내므로 따로 선택한다. 원본 명령의 대상 옵션과 시스템 헤더·타입 선언을 근거로 한다. [S1](guide-sources.md#sources)

| `.conf` 값 | 대상 | 문서상 PA 지원 시점 |
| --- | --- | --- |
| `target=win32` / `target=win64` | Windows 32 / 64비트 | 기존 지원. 최초 도입 버전 미확인 |
| `target=linux_i686` / `target=linux_x86_64` | Linux x86 32 / 64비트 | 기존 지원. 최초 도입 버전 미확인 |
| `target=linux_armv7` / `target=linux_aarch64` | Linux ARM 32 / 64비트 | 6.7부터. ARM 내장 함수 지원 포함 |
| `target=linux_riscv32` / `target=linux_riscv64` | Linux RISC-V 32 / 64비트 | 6.9부터 |

S1은 PA 6.6.3부터 `target`의 타입 크기 설정을 수정했고, 다른 크기 옵션보다 먼저 적용한다고 설명한다. 따라서 별도 크기 옵션이 남아 있으면 target 기본값을 다시 덮어쓸 수 있다. 텍스트상 줄 순서만 바꿔 해결됐다고 판단하지 않는다.

아래는 S1에 있는 타입 기본 크기 표다. 현재 컴파일러의 모든 ABI 변형을 보장하는 표가 아니며, 실제 선언·크기와 대조한다. 특히 Windows의 `long`은 이 표에서 64비트 target에도 4다.

| 타입 | win32 | win64 | linux_i686 | linux_x86_64 | linux_armv7 | linux_aarch64 |
| --- | --- | --- | --- | --- | --- | --- |
| `char` | 1 | 1 | 1 | 1 | 1 | 1 |
| `short` | 2 | 2 | 2 | 2 | 2 | 2 |
| `int` | 4 | 4 | 4 | 4 | 4 | 4 |
| `long` | 4 | 4 | 4 | 8 | 4 | 8 |
| `long long` | 8 | 8 | 8 | 8 | 8 | 8 |
| `float` | 4 | 4 | 4 | 4 | 4 | 4 |
| `double` | 8 | 8 | 8 | 8 | 8 | 8 |
| `long double` | 8 | 8 | 12 | 16 | 8 | 16 |
| `size_t` | 4 | 8 | 4 | 8 | 4 | 8 |
| 포인터 | 4 | 8 | 4 | 8 | 4 | 8 |

RISC-V의 타입 기본값 표는 조회한 원문에 없어 미확인이다. 다른 target 표에서 복제하지 않는다. ARM 64비트 설명에 `linux_armv7`을 쓴 원문 예제도 대상이 서로 맞지 않으므로 사용하지 않는다.

<a id="types"></a>

## 타입 크기·size_t·char_bit

먼저 `target`을 맞추고, 실제 컴파일러의 타입 선언·크기·비트 수와 차이가 남을 때만 검토한다. 같은 크기여도 `size_t`의 기반 타입이 다르면 선언 불일치가 남을 수 있다. 오류 문자열만 보고 값을 정하지 않는다.

| 옵션 | 원문에서 확인한 문법·예제 | 확인 범위와 주의점 |
| --- | --- | --- |
| `cs_set_type_size` | `cs_set_type_size=long_long;8`, `cs_set_type_size=short;2` | `타입;크기` 형식. `long_long`에는 공백이 없음. S1은 전체 표의 타입 크기 설정을 6.7부터, 6.6.7 이후에서도 지원한다고 기재. 다른 타입 토큰의 정확한 철자는 별도 확인 |
| 기존 크기 옵션 | `cs_int_size=4`, `cs_long_size=4`, `cs_pointer_size=4`, `cs_float_size=4`, `cs_double_size=8` | S2에 기재된 예제 값이며 허용값 전체 목록이 아님. 현재 target과 중복·충돌하는지 확인 |
| `cs_char_size` | `cs_char_size=2` | S2 예제. `cs_char_bit`와 같은 설정으로 취급하지 않음. 크기·비트 수의 실제 의미를 현재 배포본에서 검증 |
| `cs_size_t_kind` | `cs_size_t_kind=int` | S2에 있는 한 가지 예제만 확인됨. 다른 허용 토큰, 부호 처리, PA 도입 버전 미확인. `size_t`를 무조건 `int`로 바꾸라는 뜻이 아님 |
| `cs_char_bit` | S1은 기본값 8과 값 16일 때의 비트 필드 크기 예제를 설명 | 문서상 6.6.7 계열·6.7.2 계열부터 지원. `.conf`의 완전한 설정 예제·허용값 범위는 미확인 |

S2는 `cs_set_type_size=int;4` → `cs_int_size=4`처럼 변환되는 예를 싣고 있다. 그러나 `short`는 변환 대상이 없다는 옛 설명과 `char;4` → `cs_char_size=1`이라는 불일치도 있다. 이를 현재 PA의 변환 규칙으로 사용하지 않는다.

S1에는 `cs_set_size`와 `cs_set_type_size`라는 이름이 섞여 있다. 두 이름이 모든 버전에서 같은 옵션이라고 추정하거나 기존 키를 자동 치환하지 않는다.

예를 들어 `size_t` 관련 오류라면: 실제 typedef → target → 포인터·기반 정수 타입 크기 → 남아 있는 개별 크기 옵션 순으로 비교한다. 필요한 기반 타입의 문법을 로컬 자료에서도 확인할 수 없으면 해당 옵션 변경을 보류하고 필요한 확인을 보고한다.

## 전처리·preinclude·내장 선언

원본 컴파일러가 만든 전처리 결과를 분석하는지, PA가 전처리부터 하는지 먼저 구분한다. S1의 CT 타겟·ST 전처리 예제를 COVER 입력에 일괄 적용하지 않는다.

| 옵션 | 문법·예제 | 필요한 근거와 주의점 |
| --- | --- | --- |
| `cs_preinclude` | `cs_preinclude=D:/path/preinclude_header.h` | 필요한 선언·매크로가 실제 누락됐는지 확인. 경로는 검증 폴더의 복사본에 맞춤. 경로에 공백이 있을 때의 인용 규칙은 원문에서 미확인 |
| `cs_builtin_declaration` | `cs_builtin_declaration=void __enable_interrupt(void);` | 원본 컴파일러의 실제 내장 선언과 일치할 때만 검토. 인자·반환형·호출 규약 보존. 누락된 일반 헤더를 임의 선언으로 대신하지 않음 |
| `cs_add_float_type` | `cs_add_float_type=my_8byteFloat;8` | 원본 컴파일러에 같은 이름·크기의 특수 부동소수 타입이 있는 경우만 검토. S2의 예제이며 임의 타입 생성용이 아님 |
| `cs_add_integer_type` | S2는 `cs_add_float_type`과 같은 `이름;크기` 형식이라고 설명 | 실제 정수 타입 정의와 대응해야 함. 허용 크기·부호 처리의 상세 범위는 미확인 |

위 옵션의 PA 도입 버전은 원문에서 미확인이다. S2는 `cs_builtin_declaration`을 여러 줄로 설정하는 예제를 제공한다.

preinclude에서 시스템 헤더를 읽으면 해당 헤더의 include 경로도 맞아야 한다. 이미 존재하는 선언·매크로와 중복되지 않게 하고, 이미 전처리된 입력에 내장 매크로 묶음을 무조건 추가하지 않는다.

매크로 차이를 확인할 때는 같은 컴파일러·대상·include·매크로 옵션으로 만든 전처리 결과끼리 비교한다. S1은 GNU/Clang의 `-E -dD`, MSVC의 `/E /d1PP`를 조사 예로 든다. 현재 컴파일러가 해당 옵션을 받는지 확인하고 복사본 작업 폴더에서 수행하며, 이 출력 자체를 PA 복구 성공 증거로 사용하지 않는다.

<a id="encoding"></a>

## 문자 인코딩

S2에는 `cs_encoding`이라는 옵션 이름만 있다. **허용 인코딩 이름·값 구분 형식·PA 도입 버전은 미확인**이다. 이 문서는 `UTF-8`, `CP949`, `EUC-KR` 등을 옵션 값으로 사용할 수 있다고 보장하지 않는다.

화면에서 깨진 글자만으로 인코딩 오류를 확정하지 않는다. 원본 바이트, BOM, 실제 컴파일러의 입력 인코딩 옵션, 오류 위치를 비교한다. 설정 복사본도 원래 인코딩·BOM·개행을 유지한다.

같은 PA 배포본에 동봉된 로컬 설명서나 검증된 설정이 있으면 정확한 문법을 확인한다. 근거가 없으면 추측한 `cs_encoding` 값을 추가하거나 파일을 자동 재저장하지 않고, 확인이 필요한 값과 바이트 근거를 보고한다. Notion 접속은 요구하지 않는다.

## 수동 검토 옵션

아래는 기존 설정을 이해하고 수동 검토하기 위한 정보다. `cs_ignore_*`, `cs_replace_code*`, `cs_disable_keyword`, `cs_allow_*`는 이 스킬의 자동 복구 후보에서 제외한다. 코드가 사라지거나 진단이 약해지는 변경은 오류 수 감소만으로 의미 보존을 입증할 수 없다.

| 옵션·검색어 | 원문이 설명하는 동작 | 검토할 내용 |
| --- | --- | --- |
| `cs_replace_code` | `cs_replace_code=원문<cs_delim>치환문` 형식의 문자열 치환 | S1은 문자열 안의 따옴표에 추가 묶음이 필요한 예를 제공. 해당 PA의 인용 처리·매칭 범위를 확인하기 전 자동 생성하지 않음 |
| `cs_replace_code_re` | `cs_replace_code_re=정규식<cs_delim>치환문` 형식의 정규식 치환 | 빈 치환문이면 삭제. 함수 호출·분기·초기화까지 사라지는지 확인. 넓은 정규식 예제를 복구안으로 복사하지 않음 |
| `cs_ignore_paren=guard` | S4에 기록된 과거 `guard(...)` 무시 사례 | `/sdl`, `_CRT_GUARDOVERFLOW`, 실제 전처리의 `__declspec(guard(overflow))`를 조사하는 단서. 현재 버전에서도 필수인 옵션으로 일반화하지 않음 |
| `cs_ignore_*`, `cs_asm_*`, `cs_paren_asm` | 특정 토큰·영역·어셈블리 구문 등을 무시하는 옵션군 | 실제 삭제 범위, 함수 호출·메모리 접근·커버리지 영향 확인. 옵션 이름만으로 안전하다고 판단하지 않음 |
| `cs_disable_keyword`, `cs_allow_*` | 키워드 해석 변경 또는 느슨한 구문·타입 허용 | 원본 컴파일러에서도 잘못된 코드를 허용하게 되는지 확인 |
| `display_error_number` | S6에서 진단 번호를 출력하는 플래그로 소개 | 오류를 식별하는 보조 정보. 번호 출력만으로 원인이나 성공을 판단하지 않음 |
| `diag_warning=1097` | S6의 `guard` 관련 진단 수준 변경 사례 | 진단 억제와 원인 해소를 구분. 경고로 바뀌었다는 이유만으로 복구 성공으로 판정하지 않음 |

이 표에 나온 옵션들의 PA 도입 버전은 조회 원문에서 미확인이다. 수동 검토가 필요하면 매칭되는 코드와 변경 전후 의미를 제시하고, 최종 실행 상태는 [PA 실행 계약](pa-runtime.md)으로 판단한다.
